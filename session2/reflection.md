Reflection

Q1. How do Issues and pull requests together support change control?

Issues help team members record problems, tasks, and proposed changes in a project. Pull requests allow developers to submit their changes for review before merging them into the main branch. By connecting pull requests to Issues, the team can track why a change was made and what was changed. This makes the development process more organized and easier to manage.

Q2. Why did the conflict in Part 4 happen, and how could a team reduce such conflicts?

The conflict happened because Branch A and Branch B changed the same line in the same file with different values. Git could not automatically decide which change should be kept when both branches were merged. A team can reduce such conflicts by communicating regularly, dividing tasks clearly, and frequently updating their branches with the latest changes from the main branch.

Q3. What would be lost if people merged straight into main without a pull request?

Without pull requests, the team would lose the opportunity to review changes before they are merged into the main branch. Mistakes and bugs might go unnoticed because there would be no proper review process. Team members would also have less opportunity to provide feedback and discuss improvements. This could make the project harder to maintain and manage.
